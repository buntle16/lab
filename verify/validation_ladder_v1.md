# 검증 사다리 — 트레이딩 전략을 "맞았다"고 말하기 전에 거치는 순서

> **English summary.** A short, honest method for testing algorithmic trading ideas without fooling yourself: declare the pass condition before looking at results, fix the number of tests in advance, spend a sealed holdout exactly once, audit the material for look-ahead leakage first, and audit every wrong answer after each test. This page describes the method only. It contains no live thresholds, signals or parameters — those are intentionally not public.

이 문서는 **방법**만 공개한다. 실제 운용 조건·문턱·숫자는 싣지 않는다. 공개하는 것은 "어떻게 시험하고 어떻게 기각하는가"다.

## 왜 사다리인가

백테스트는 결과를 보고 나서 기준을 고르면 거의 항상 통과한다. 그래서 시험을 **계단(판)** 으로 나누고, 계단마다 통과 조건을 먼저 적어 둔다. 통과하지 못하면 다음 계단으로 올라가지 않는다.

## 규칙 7개

1. **통과 조건은 결과를 보기 전에 적는다.** 판마다 "무엇이 나오면 통과, 무엇이 나오면 기각"을 먼저 쓴다. 사후에 바꾸지 않는다. 바꾸고 싶으면 새 판으로 연다.
2. **시험 횟수를 미리 정한다.** 같은 자료를 여러 번 돌려 좋은 것만 고르는 일(다중 비교)을 막는다. 횟수를 늘리고 싶으면 다음 판으로 넘긴다.
3. **봉인 자료는 한 번만 쓴다.** 개발에 쓰지 않은 구간을 따로 잠가 두고, 마지막에 한 번만 열어 판정한다. 열고 나면 그 구간은 더 이상 봉인이 아니다.
4. **재료 검문이 먼저다.** 분석 전에 자료가 시험에 쓸 수 있는 상태인지 본다. 가장 중요한 검문은 **룩어헤드(미래 정보 누수)** 다. 시각 t의 판단에 t 이후에 알게 되는 값이 들어가 있지 않은지, 단위(봉·건)가 맞는지, "상태" 칸과 "결과" 칸이 섞이지 않았는지 확인한다.
5. **시험 직후 오답 검산.** 틀린 건은 원인을 가른다 — 읽기 오류 / 표에 없는 장면 / 답지 밖 / 가설이 틀림. 맞은 건도 실질인지 우연인지 가른다.
6. **자기 채점 금지.** 만든 사람(또는 모델)이 자기 결과를 채점하지 않는다. 채점 자료는 만든 쪽이 못 건드리는 원자료에서 직접 조인한다. 결론을 내리기 전에 원자료 한 칸을 직접 열어 검산한다.
7. **반대 사례를 항상 같이 낸다.** 비슷해 보였는데 무너진 사례를 같이 대고, 무엇이 둘을 갈랐는지 칸으로 적는다. 대지 못하면 "보류"다.

## 기초작업 표준 (0~7단계)

데이터 작업은 다음 순서를 통과한 재료만 분석에 쓴다.

| 단계 | 내용 |
|---|---|
| 0 | **현장 구조도** — 데이터를 보기 전에 참여자·흐름·칸이 어디에서 오는지·사각지대부터 그린다. 점에서 시작하지 않는다 |
| 1 | 들여오기 — 원자료를 건드리지 않고 복사해 들인다 |
| 2 | 정렬 — 시각·단위를 맞춘다 |
| 3 | 라벨 — 상태 라벨과 결과 라벨을 분리한다 |
| 4 | 모듈 — 갈아 끼울 수 있는 단위로 쪼갠다 |
| 5 | 검수 — 누수·결측·행수를 점검한다 |
| 6 | 정의서 — 칸의 정의를 먼저 확정한다. 추가만 하고 번호는 재사용하지 않는다 |
| 7 | 출고 — 다음 판이 쓸 수 있는 형태로 내보낸다 |

뼈대는 **고전적 방법론**을 따르고, 속도는 AI가 낸다. AI가 새 방법이나 새 문턱을 만들어 내면, 고전의 어느 칸에 해당하는지 대고 없으면 "가설"로 표시한다.

## 리딩 유형은 따로 채점한다

현물이 끌고 가는 장면, 선물이 끌고 가는 장면, 둘이 섞인 장면을 **한 통에 넣고 평균 내지 않는다.** 유형별로 따로 채점하고, 섞인 유형을 한쪽에 합치지 않는다.

## 기각 기록은 자산이다

이 방법이 일하고 있다는 증거는 통과한 전략이 아니라 **기각된 가설의 목록**이다. 기각 장부에는 가설, 시험 조건, 기각 이유, 다음에 같은 실수를 막는 점검 항목을 적는다. 예시(조건과 값은 생략):

- 여러 칸을 조합한 가설이 짧은 관찰 창에서는 기각됐다. 관찰 창을 길게 잡고 다시 채점하자 **한 축만** 살아남았고, 나머지 조합은 우연으로 처리했다.
- 한 번 통과한 규칙이 두 번째 회차에서 재현되지 않았다. 첫 회차를 근거로 올리지 않고 기각으로 닫았다.
- 자료의 일부만 채워진 상태로 시험했음이 뒤늦게 드러나, 그 판 전체를 **무효**로 처리하고 번호를 폐기했다.

기각은 실패가 아니라 다음 판의 출발점이다. 같은 질문을 두 번 시험하지 않게 해 준다.

## 하지 않는 것

- 결과를 본 뒤 기준을 바꾸지 않는다.
- 통과한 판의 값만 골라 보여 주지 않는다.
- 실전 값(조건·문턱·크기)을 공개하지 않는다. 방법은 공개하고 구상은 공개하지 않는다.
